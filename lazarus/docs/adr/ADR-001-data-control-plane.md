# ADR-001: Data Plane と Control Plane を分ける / Event Bus は Control Plane 専用

- 状態: 採用 (Phase 0)
- 対応する Baseline: v1.1 §5.1, §12, §19 ADR-001
- 実装: `units/EventBus.pas`
- 検証: `test/test_eventbus.lpr`

## 決定

**Event Bus は Control Plane 専用**とし、Audio / IQ / Spectrum / DSP Frame は
一切載せない。それらは Ring Buffer や共有バッファ（Data Plane）で扱う。

## 「気をつける」では守れないので型で守る

境界を規約だけで維持するのは無理なので、載せられない構造にした。

```pascal
TBusEvent = record
  Kind: TBusEventKind;
  I1, I2: Int64;        // 汎用の数値スロット
  D1, D2: Double;
  Text: string;         // 低頻度イベント専用
  TimestampUtc: TDateTime;
  Source: string;
end;
```

**固定長のレコード**である。配列もストリームも持てないので、そもそも波形を
載せられない。`SizeOf(TBusEvent) = 64` バイトで、これは回帰テストで
固定してある（意図しない拡張に気づけるようにするため）。

文字列スロットが 1 本だけあるのは例外で、確保を伴うため低頻度のイベント
（エラー、ステータス、コールサイン）専用と決めている。高頻度の
`DecodedSymbol` は数値スロットだけを使う（X-04 との整合）。

## スレッドとの関係

発行側は音声ワーカー、購読側は UI であることが多い。そこで
「発行は任意スレッドから即座に戻り、配送は 1 つの消費スレッドでまとめて行う」
形にした。

```
Publish (任意スレッド) → 有界リングバッファへコピー
                       → 未スケジュールなら Queue を 1 回だけ積む
DispatchPending (メイン) → 溜まったぶんを順に購読者へ配る
```

これは `ModemUI` で先に確立した方式（有界FIFO＋単一ドレイン＋在席カウンタ）
をバス側の責務として引き上げたものである。有界にしてあるのは、UI が詰まった
ときにメモリが伸び続けないようにするため。溢れたら古いものから捨て、
捨てた件数を数える。

## 購読者の例外を封じ込める（§12）

「Subscriber 例外によって Event Bus 全体を停止させない」が要求されている。
1 つの購読者が投げた例外で他の購読者への配送が止まると、障害が波及する
（B-04 / Z-06 Fault Isolation）。

購読者ごとに例外境界を置き、捕まえた例外は件数を数えて
`OnSubscriberError` で通知したうえで、**残りの購読者への配送を続ける**。
通知先が投げた例外も封じ込める。

配送はイベントと購読者一覧をロック下で写し取り、呼び出しはロック外で行う。
購読者がバスへ発行し返してもデッドロックしない（回帰テスト 5 で確認）。

## 観測（Z-01）

`PublishedCount` / `DeliveredCount` / `DroppedCount` / `SubscriberErrorCount`
を公開する。`DroppedCount` が 0 でなければ購読側が追いついていない、
`SubscriberErrorCount` が増えていればどこかの購読者が壊れている、と
外から分かる。

## 代替案と却下理由

**イベントをクラスにする。** 種別ごとに型を持てて安全だが、発行のたびに
確保が走る。発行元は音声ワーカーなので X-04 に反する。固定長レコードに
汎用スロットを持たせる方式は型安全性を犠牲にするが、境界の維持と
realtime 制約を優先した。

**購読者の例外を握り潰さず再送出する。** 呼び出し元（メインスレッドの
ドレイン）に伝わってアプリが落ちる。§12 が明確に禁じている。

## `ModemUI` の移行 (完了)

`ModemUI` は自前の有界FIFO・単一ドレイン・合流を持っていたが、同じ仕組みが
バス側にも要るため二重に持つ理由がない。publisher と subscriber の 2 役に
徹する形へ作り直した。既存の 43 件のスレッド安全性テストは**変更せずに**
通っている。

副次的な効果として、ロガーや Plugin や Observability が同じイベントを
`ModemUI` を経由せずに購読できるようになった。バスは外から渡せる
(`TModemUI.Create(ABus)`)。渡さなければ自前で作って所有する。

### 移行にあたってバスへ足したもの

**合流 (`PublishLatest`)。** 周波数や S メーターは更新頻度が高く、FIFO に
積むと復調文字を押し出す。同じ種別の未配送イベントがあればその場で
上書きし、積み増さない。`RigChanged` / `ContestScoreChanged` /
`AwardProgressChanged` も同じ性質なので、バス共通の機能として持たせた。

**`I3` スロット。** 復調結果が「文字・尺度種別・尺度・第2候補件数」を運ぶ
のに数値スロットが足りなかった。72 バイトになったが固定長は保っている。

### テストが薄かった点を補強した

移行後、既存 43 件は通ったが、**修正をわざと戻しても落ちなかった**。

- 購読解除を外しても落ちない → `ModemUI` が自前バスを所有する経路では
  バスごと解放されるため露見しない。**共有バスの場合だけ**問題になる。
- 合流をやめても落ちない → `test_modem` では周波数が 4 回しか変わらず、
  押し出しが起きない。

そこで 2 件を追加した (`test_threadsafety` 14 / 15)。今度は戻すと落ちる。

```
反証: 購読解除を外す → [NG] 破棄時に購読を外す
反証: 合流をやめる   → [NG] 文字 20 件がすべて届く (実際: 0)
                       [NG] 押し出されていない (捨てた件数 456)
```
