# ADR-010: 観測は「出来事の列」と「数値の分布」に分け、記録は確保しない

- 状態: 採用 (Phase 0)
- 対応する Baseline: v1.1 §14 Z-01 Observability, Z-04, §17 評価指標
- 実装: `units/Observability.pas`
- 検証: `test/test_observability.lpr`

## 二つの目的は要求する形が違う

v1.1 は Z-01 の目的を「障害診断とアルゴリズム改善の二つ」と書いている。
この二つは必要な形が違う。

| 目的 | 必要な形 | 頻度 |
|---|---|---|
| 障害診断 | 出来事の列。順序と時刻が要る | 低い |
| アルゴリズム改善 | 数値の分布。個々の値より統計 | 高い |

一方に寄せると他方が使えない。SNR を出来事として 1 件ずつ残すとリングが
すぐ埋まり、逆に障害を統計にすると「何がどの順で起きたか」が消える。
そこで記録を 2 種類に分けた。

- `TObsLog` — 出来事を時系列で残す（有界リング）
- `TObsMetric` — 数値の統計を積む（件数・最小・最大・平均・分布・予算超過）

## 記録は確保しない

記録は音声スレッドから起きる。観測のために deadline を落としては本末転倒
なので（ADR-009）、記録側を **確保しない・伸びない** 設計にした。

- 記録は固定長レコード。発生元の名前は動的文字列ではなく固定長の文字配列
  （`array[0..23] of AnsiChar`）で持つ。代入しても確保も参照カウント操作も
  起きない。
- リングは生成時に確保し、以後伸びない。溢れたら古いものから捨て、
  捨てた件数を数える。
- ロックは専用の短いものを使う。メモリマネージャのロックが realtime で
  問題なのは「保持時間が長い」からではなく **確保の作業量が有界でない**
  からであり、数命令で抜けるロックは性質が違う。

これは回帰テストでメモリマネージャを差し替えて実測している。

```
出来事 2000 件の記録: 確保 0 回
統計 2000 件の記録  : 確保 0 回
```

`TObsLog` には文字列を受ける `Add` と固定長名を受ける `AddRaw` の両方が
ある。realtime 経路では `AddRaw` を使う。

## 記録経路は Event Bus への購読 1 つで立てる

`TObsBusRecorder` はバスを購読して記録するだけである。**発行元
（モデム・エンジン・リグ）には一切手を入れていない。** ADR-001 でバスを
Control Plane の通り道にしたので、購読を足せば記録経路が立つ。

診断と改善に効くものだけを残す。周波数や S メーターのような合流イベントは、
値そのものより統計の方が意味があるので出来事としては残さない。

## 副産物: 捨てられていた情報を通した

実装中に、記録すべきなのに捨てられていた情報が 2 つ見つかった。

**PortAudio の overflow / underflow。** 「データは取れているから致命的では
ない」として黙って握り潰していた。黙って捨てると
「復調がときどき化けるが原因が分からない」という最も困る状態になる。
回数を残せば、音が悪いのか設定が悪いのかを切り分けられる。

**Evidence の SNR と復調戦略名。** `ModemUI` がバスへ発行するとき、
SNR を 0 に、発行元を自分の名前（`'ModemUI'`）にしていた。Phase 3 で複数
戦略を並列評価したとき、記録から戦略を区別できなければ「どの戦略が良いか」
を測れない。Evidence の `DecoderName` をそのまま発行元にした。

後者は、バスへ直接発行するテストでは気づけなかった。実経路
（モデム → ModemUI → バス → 記録）を通すテストを足して初めて捕まった。

## エンジンのブロック処理時間は注入型にした

Z-04 の判定材料になるので `TModemEngine` から測れるようにしたが、
`BlockMetric` を設定したときだけ測る。設定しなければ時刻取得すらしない。

観測のために DSP 層が診断機構を知る必要はないし、観測が既定で有効だと
「測っているせいで遅い」という疑いを常に抱えることになる。

## 代替案と却下理由

**記録を文字列のログにする。** 人が読みやすいが、書式化のたびに確保が走る。
realtime 経路から呼べなくなり、いちばん知りたい場所が記録できない。
書式化は読み出し側（`Export_`）でだけ行う。

**出来事の種類を文字列にする。** 自由度は上がるが、確保が起きるうえ集計が
できない。列挙にした。
